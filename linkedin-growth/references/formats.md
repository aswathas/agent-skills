# Formats

Six shapes. Pick the one the material actually fits; do not force a topic into
a carousel because carousels perform.

## 1. Text post (default)

150–250 words. Hook, re-hook, three to six short blocks, question or next step,
hashtags.

```
[hook: two lines, under 110 chars]

[re-hook: the mechanism or the stakes]

[body: one idea, broken into short paragraphs, at least one number]

[the limitation, stated plainly]

[link, on its own line]

#tag #tag #tag
```

## 2. Document carousel (highest engagement, most work)

LinkedIn posts a PDF as a swipeable carousel — a document post, not images. You
cannot attach images to the same post, so the images go **inside** the PDF.

- 6–12 pages. Page 1 is the hook, page 2 is the stakes, the middle is one idea
  per page, the last page is the CTA.
- Every page readable at thumbnail size: one idea, large type, no paragraphs.
- Caption is short — the carousel carries the content.
- Publish with `postiee post --pdf <file> --title "<title>"`.

A good carousel is a report someone would screenshot. A bad one is a slide deck
with 40 words per page.

## 3. Code teardown

One mechanism, with the mechanism visible. Include a short code block or an
exact path. The reader should be able to check the claim.

```
[hook: the surprising behaviour]

[one line of context]

[what the code does, in three or four arrows]

[why the obvious fix is wrong]

[the fix, one line]

[what this cost you or saved you]
```

## 4. News take

The news in one line, then the practitioner angle. Never a summary.

- Line 1: what happened, with the source.
- Line 2–4: what it changes for someone running agents or shipping developer
  tools.
- Line 5: what to check before believing it.
- Line 6: the question.

If the story has no angle from first-hand work, skip it.

## 5. Build log

For something shipped this week.

```
[hook: the outcome or the number]

[what it is, one sentence]

[three or four bullets: capability, measurement, limitation]

[what is next]

[link]
```

This is the pillar that converts strangers into followers, because it is proof
rather than opinion.

## 6. Milestone / personal

Hackathons, prizes, teammates, a first contribution merged. Keep it specific:
the detail, not the trophy.

Rules:
- Name the people and the organisation, with a real mention only if a URN
  exists; otherwise name and link.
- One lesson, not five.
- Do not turn a milestone into a motivational post.

## Length by format

| Format | Words | Reading time |
|---|---|---|
| Text | 150–250 | 40–60s |
| Carousel caption | 60–120 | 15–25s |
| Teardown | 200–300 | 60–90s |
| News take | 120–180 | 30–45s |
| Build log | 150–220 | 40–60s |
| Personal | 150–250 | 40–60s |

## The first comment

Put the second link, the repo, or the longer context in the first comment. It
keeps the post body clean and gives the author a reason to be in the thread.
